# Shared sing-box config contract

## Source of truth

`core:config` is the Android rewrite source of truth for sing-box JSON. It mirrors the portable subset of desktop `src/lib/singbox.js` while keeping Android-specific TUN/runtime constraints explicit.

The module is pure Kotlin/JVM:

- no `android.*`;
- no `org.json`;
- no SharedPreferences or files;
- no Compose;
- no libbox APIs.

## Inputs

```text
List<ConfigNode>
ProxySelection
SingBoxOptions
logPath?
```

`ConfigNode` separates persisted identity from connection properties. Tags remain `n<id>`, so URLTest delay events and the existing Android UI keep their stable mapping.

`SingBoxOptions` is an immutable build snapshot. Android maps its current persisted `Options.Data` into this DTO immediately before start/reload.

## Determinism

For equal ordered inputs the builder emits byte-identical compact JSON. It also:

- rejects an empty node list;
- deduplicates repeated persisted IDs before emitting outbounds;
- falls back to `auto` when a concrete selection is absent;
- validates DNS schemes, hosts and ports before libbox startup.

Golden tests compare parsed JSON for readability and separately assert byte-level repeatability.

## Protocol contract

Supported native libbox outbounds:

- VLESS;
- VMess;
- Trojan;
- Shadowsocks, including SIP002 plugin metadata;
- Hysteria2, including obfs, bandwidth and public-key pin;
- TUIC, including congestion, UDP relay, 0-RTT and `disable_sni`.

Stream multiplex is emitted only for non-QUIC outbounds. Hysteria2 and TUIC already multiplex streams through QUIC and must not receive sing-box stream multiplex options.

## TLS and transports

The builder supports:

- TLS and Reality;
- uTLS fingerprint;
- ALPN;
- TCP or TLS-record fragmentation;
- optional fragment fallback delay;
- padding and mixed-case SNI tricks;
- WS, gRPC, HTTP/H2 and native xHTTP transports.

xHTTP `extra` is never merged blindly. Only fields known by the pinned hiddify-sing-box 1.13 schema are emitted. Xray-style `downloadSettings` are translated into sing-box names, including nested TLS/Reality options. Unknown fields are dropped because the runtime parser is strict and one unsupported key can reject the entire config.

## DNS and routing

The Android contract builds:

- protected remote DNS through `proxy`;
- bootstrap/direct DNS without a proxy detour;
- IPv4-only, prefer-IPv4, prefer-IPv6 and IPv6-only strategies;
- optional FakeDNS;
- local/private bypass;
- regional geoip/geosite rules;
- remote ad/malware/phishing/cryptominer rule sets.

The direct resolver intentionally does not contain `detour: "direct"`. Current sing-box 1.13 rejects a detour to an otherwise empty direct outbound. This differs from an older Android builder comment and follows the current desktop contract.

## Golden coverage

`golden-default-vless.json` freezes the safe default Android config.

`golden-feature-vless.json` freezes the interaction of:

- IPv6 TUN;
- custom TLS/UDP DNS;
- FakeDNS;
- region routing;
- ad blocking;
- TLS fragmentation/tricks;
- stream multiplex;
- custom health-check interval and log path.

Additional structural tests build all shared parser fixtures and verify protocol-specific fields, xHTTP translation, deduplication and validation failures.

## Android adapter

`app/.../vpn/ConfigBuilder.kt` remains only for compatibility with existing `VpnService` and UI code. It must not acquire new JSON-building rules. New config behavior belongs in `core:config` with a test first.

## Runtime verification still required

Compile, lint and golden tests prove the schema generated by our code is stable. Before the draft PR becomes ready, a debug APK still needs a device smoke test covering:

1. connect/disconnect with Auto;
2. one TCP/TLS node;
3. one QUIC node;
4. subscription refresh while Auto is selected;
5. DNS resolution with default options;
6. an xHTTP node with real `downloadSettings` when available.
